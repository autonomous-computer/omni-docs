# Client API Quickstart

OMNI Client API v1 is currently in **internal beta** with allowlisted accounts.

## 1. Create an API key

Use an authenticated Omni session token (your normal app auth) and create a key:

```bash
curl -X POST https://agent-backend.omnibrief.app/api/client/keys \
  -H "Authorization: Bearer <omni_user_jwt>" \
  -H "Idempotency-Key: idem_create_key_001" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "internal-beta-main",
    "mode": "live",
    "scopes": ["fred.read", "mcp.tools.read"]
  }'
```

Response includes the key once:

```json
{
  "data": {
    "id": "key_xxx",
    "apiKey": "omni_live_...",
    "mode": "live"
  }
}
```

## 2. Call Client API v1

```bash
curl "https://api.omnibrief.app/v1/fred/search?q=unemployment&limit=5" \
  -H "Authorization: Bearer omni_live_..." \
  -H "X-Request-Id: req_demo_001" \
  -H "Omni-Version: 2026-02-17"
```

## 3. MCP tool catalog

```bash
curl "https://api.omnibrief.app/v1/mcp/tools" \
  -H "Authorization: Bearer omni_live_..."
```

## 4. Idempotent POST tool invoke

```bash
curl -X POST "https://api.omnibrief.app/v1/mcp/invoke" \
  -H "Authorization: Bearer omni_live_..." \
  -H "Idempotency-Key: idem_001" \
  -H "Content-Type: application/json" \
  -d '{
    "tool": "fred.search",
    "arguments": { "q": "cpi", "limit": 3 }
  }'
```

## Internal beta notes

- Access is allowlist-gated.
- Billing infrastructure is active and usage is metered from successful calls.
- Public beta infrastructure is deployed but remains gated off.
