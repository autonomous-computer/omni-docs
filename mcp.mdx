---
title: "Model Context Protocol (MCP)"
description: "Connect an MCP client to the hosted TUROS server, verify discovery, and let agents find tools with tools.search."
---

TUROS hosts an MCP server at `https://api.secapi.ai/mcp`, so an MCP-aware client can discover and call SEC research tools without you writing an integration. `GET /mcp` is public discovery metadata. Authenticated JSON-RPC requests, including tool calls, are `POST /mcp` with an API key in `x-api-key`.

Keep the key in the client's process environment or secret store - not in a prompt, URL, or repository.

## Install

Create a key in the [TUROS dashboard](https://turos.app), then expose it to the client process:

```bash
export SECAPI_API_KEY="secapi_..."
```

### Claude Code

```bash
claude mcp add --transport http secapi https://api.secapi.ai/mcp \
  --header "x-api-key: $SECAPI_API_KEY"
```

Restart the client after changing its environment or configuration.

### Other clients

The CLI generates the configuration for supported clients:

```bash
secapi mcp install --client <claude-code|claude-desktop|cursor|windsurf|project>
```

For clients that accept portable remote HTTP MCP configuration, use their supported environment-variable syntax for this shape:

```json
{
  "mcpServers": {
    "secapi": {
      "url": "https://api.secapi.ai/mcp",
      "headers": { "x-api-key": "${SECAPI_API_KEY}" }
    }
  }
}
```

While you're wiring things up, use a `secapi_test_` key - test-key traffic is free. See [Test mode](/test-mode).

## Verify discovery

`GET /mcp` is public and returns the deployed server's connection metadata, including `protocolVersion`, `capabilities`, and a `distribution` payload with the streamable HTTP transport and current install hints:

```bash
curl --fail-with-body -sS https://api.secapi.ai/mcp
```

A successful `GET /mcp` proves discovery is available - it doesn't verify an API key or authorize a tool call. Clients that require OAuth protected-resource metadata can discover it at `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server`.

## Discover tools with tools.search

Don't rely on an embedded tool catalog. TUROS ships `tools.search` and `tools.describe` so a client can find the current tools and inspect their input schemas at runtime. They're TUROS tools, not JSON-RPC methods - the client invokes them through authenticated `tools/call` requests.

A good first prompt after the client shows TUROS tools:

```text
Use tools.search to find issuer resolution, latest filing, and filing
section tools. Use tools.describe on each selected tool before calling it.
Resolve AAPL, retrieve its latest 10-K, then retrieve Item 1A. Return the
company name, accession number, form, filing date, filing URL, requestId,
and a short Item 1A summary. State when a field is absent instead of
inferring it.
```

Treat structured output and returned identifiers as the source record. Provenance, freshness, truncation, and trace context are available only when the selected tool returns them.

## Errors

- **No tools appear** - reload the configuration and confirm `SECAPI_API_KEY` is visible to the client process.
- **`401` or `403`** - repair or rotate the API key. Don't substitute a browser bearer token.
- **JSON-RPC validation error** - send one JSON-RPC 2.0 request object with the required request ID. TUROS doesn't support batch JSON-RPC requests.
- **`-32004`** - the execution budget for the call was exhausted. Narrow the request.
- **`-32005`** - the AI-query or MCP quota was reached. Stop and check `GET /v1/limits`.
- **`-32006`** - tool protection refused the call. Follow the response rather than replaying the job.

For validation, billing, quota, and timeout results, retain the returned request ID, narrow the next call, and follow the response instead of replaying a broad job. For unattended agents, add the preflight and stop conditions from [TUROS Agent](/ai/agent).
