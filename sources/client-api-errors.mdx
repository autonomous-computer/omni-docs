# Client API Errors

OMNI Client API uses a stable, machine-readable error contract across REST (`/v1/...`) and hosted MCP (`/mcp`).

This page is the authoritative **v1 error-code registry** for integrations.

## Stability guarantees

- `error.type` and `error.code` are stable and safe for programmatic branching.
- `error.message` is human-readable and may change; never parse it.
- `error.request_id` is the support/debug join key. Always log it.
- New codes may be added in beta, but existing codes are not silently repurposed.

## REST error envelope

```json
{
  "error": {
    "type": "invalid_request | auth_error | permission_error | rate_limit_error | api_error",
    "code": "machine_readable_code",
    "message": "Human-readable message",
    "request_id": "req_xxx"
  }
}
```

## Diagnostic headers to log

- `X-Request-Id`: echoed request id (or generated by OMNI)
- `Omni-Required-Scopes`: present on some `403 insufficient_scope`
- `Idempotency-Replayed: true`: served from idempotency replay cache
- `Retry-After`: present on some `429` responses

## HTTP category mapping

| `error.type` | Typical HTTP status |
| --- | --- |
| `invalid_request` | 400, 409 |
| `auth_error` | 401, 403 |
| `permission_error` | 403 |
| `rate_limit_error` | 429 |
| `api_error` | 5xx |

## Authoritative v1 code registry

The table below reflects code-level behavior in `omni-system` (`webapp/client_api.py`, `webapp/client_api_mcp_gateway.py`).

| `error.type` | `error.code` | HTTP | Retry? | Trigger | Action |
| --- | --- | --- | --- | --- | --- |
| `auth_error` | `missing_api_key` | 401 | No | Missing/malformed `Authorization` header | Send `Authorization: Bearer omni_live_...` |
| `auth_error` | `invalid_api_key` | 401 | No | Invalid/revoked key | Rotate/create a valid key |
| `auth_error` | `auth_rejected` | 403 | No | Auth control-plane deny | Check allowlist, account state, entitlements |
| `permission_error` | `insufficient_scope` | 403 | No | Required scope missing | Add required scopes (check `Omni-Required-Scopes`) |
| `rate_limit_error` | `rate_limit_exceeded` | 429 | Yes | Burst/sustained rate limit exceeded | Honor `Retry-After`; apply backoff + jitter |
| `invalid_request` | `invalid_parameter` | 400 | No | Query/body param parse/validation failed | Correct param shape/range |
| `invalid_request` | `invalid_json` | 400 | No | Body is not valid JSON | Fix serialization; send `Content-Type: application/json` |
| `invalid_request` | `invalid_payload` | 400 | No | Body schema invalid for endpoint/tool method | Fix required fields/types |
| `invalid_request` | `missing_idempotency_key` | 400 | No | Missing key for mutating call | Add `Idempotency-Key` |
| `invalid_request` | `idempotency_conflict` | 409 | Yes | Same idempotency key in-flight | Retry with same key after short delay |
| `invalid_request` | `unknown_tool` | 400 | No | Tool name not found | Call `tools/list`; use returned name |
| `invalid_request` | `missing_q` | 400 | No | Missing `q` in `fred.search` | Provide `q` |
| `invalid_request` | `missing_series_id` | 400 | No | Missing `series_id` in `fred.series` | Provide valid series id |
| `invalid_request` | `fred_invalid_request` | 4xx | No | Upstream FRED rejected request | Validate IDs/params/date window |
| `api_error` | `auth_backend_unavailable` | 503 | Yes | Auth backend unavailable | Retry with bounded backoff |
| `api_error` | `invalid_control_plane_response` | 503 | Yes | Malformed auth/control-plane payload | Retry; escalate with `request_id` if persistent |
| `api_error` | `service_disabled` | 503 | Yes | API kill switch enabled | Retry later; monitor status |
| `api_error` | `fred_upstream_error` | 5xx | Yes | Upstream FRED failure | Retry with backoff |
| `api_error` | `mcp_invocation_failed` | 5xx | Yes | Tool invocation failure path | Retry idempotently; inspect tool arguments/scopes |
| `api_error` | `mcp_internal_error` | 500 | Yes | Hosted MCP internal failure | Retry idempotently; escalate with request id |

## Endpoint-family error quick map

| Endpoint family | Common codes |
| --- | --- |
| `/v1/health`, `/v1/openapi.json` | `missing_api_key`, `invalid_api_key`, `auth_rejected`, `rate_limit_exceeded`, `service_disabled` |
| `/v1/fred/*` | auth/scope/rate-limit codes + `missing_q`, `missing_series_id`, `fred_invalid_request`, `fred_upstream_error` |
| `/v1/mcp/invoke` | auth/scope/rate-limit codes + `missing_idempotency_key`, `invalid_json`, `invalid_payload`, `unknown_tool`, `idempotency_conflict`, `mcp_invocation_failed` |
| Hosted MCP (`/mcp`) | JSON-RPC errors with `error.data.omni_code` mapping to REST-like codes |

## Hosted MCP JSON-RPC mappings

Hosted MCP is JSON-RPC compliant and includes `error.data.omni_code` for cross-surface handling.

### Code mapping

| JSON-RPC code | Meaning | Typical `omni_code` source |
| --- | --- | --- |
| `-32700` | Parse error | JSON parse failure |
| `-32600` | Invalid request | malformed request object/method |
| `-32601` | Method not found | unsupported MCP method |
| `-32602` | Invalid params | invalid params + mapped `invalid_request` codes |
| `-32001` | Auth/permission | mapped `auth_error` / `permission_error` codes |
| `-32002` | Rate limit | mapped `rate_limit_error` codes |
| `-32603` | Internal error | mapped `api_error` codes (`mcp_internal_error`, etc.) |

### Example hosted MCP error

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "error": {
    "code": -32001,
    "message": "Unauthorized",
    "data": {
      "omni_code": "invalid_api_key",
      "request_id": "req_123"
    }
  }
}
```

## Retry policy

| Condition | Retry? | Rule |
| --- | --- | --- |
| `429 rate_limit_exceeded` | Yes | Honor `Retry-After`; otherwise backoff + jitter |
| `503 auth_backend_unavailable` | Yes | Exponential backoff with jitter |
| `409 idempotency_conflict` | Yes | Retry with the same idempotency key |
| `invalid_request` input errors | No | Fix payload/params first |
| `auth_error` / `permission_error` | No | Fix key/scopes first |

## Recommended handling rules

1. Log both client-generated `X-Request-Id` and OMNI `request_id` on every failure.
2. Branch on stable machine values: `error.type`, `error.code`, JSON-RPC `error.code`, and `error.data.omni_code`.
3. Reuse the same `Idempotency-Key` whenever retrying `tools/call` or `POST /v1/mcp/invoke`.
4. Treat unknown new codes as transient only if HTTP is `5xx` or JSON-RPC category is internal/rate-limit.
