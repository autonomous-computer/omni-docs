# Client API Reference

This is the operational, endpoint-by-endpoint reference for the OMNI Client API.

For schema-level request/response definitions (and interactive “try it” functionality), use:

- `Client API (Generated)` in the left navigation
- `/sources/client-api-openapi`

## Base URL

Production:

```text
https://api.omnibrief.app
```

## Authentication

All endpoints require an API key:

```http
Authorization: Bearer omni_live_...
```

## Global request headers

| Header | Required | Used for |
| --- | --- | --- |
| `Authorization: Bearer ...` | Yes | Auth to Client API and hosted MCP transport. |
| `Omni-Version: YYYY-MM-DD` | No | Behavior pinning during beta. Recommended for production integrations. |
| `X-Request-Id: req_...` | No | End-to-end trace correlation (echoed back and included in errors). |
| `Idempotency-Key: idem_...` | Sometimes | Required for mutating operations: `POST /v1/mcp/invoke` and hosted MCP `tools/call` over `POST /mcp`. |
| `Content-Type: application/json` | Sometimes | Required when sending JSON bodies (`POST /v1/mcp/invoke`, `POST /mcp`). |

## Global conventions (non-negotiable)

- Errors: REST endpoints return a consistent `{"error": {...}}` envelope. See `/sources/client-api-errors`.
- Scopes: scoped keys are strongly recommended. If a key is missing scopes, OMNI responds with `403` and `error.code=insufficient_scope` and may include `Omni-Required-Scopes` for fast diagnosis.
- Billing: successful calls (`2xx/3xx`) are billable. Failures (`4xx/5xx`) are not billable. Idempotent replays are not double-billed. Read-only retries can be billed more than once if multiple attempts succeed. See `/sources/client-api-usage-billing` and `/sources/client-api-retries`.

## Endpoint catalog

| Endpoint | Method | Scopes | Idempotency-Key | Purpose |
| --- | --- | --- | --- |
| `/v1/openapi.json` | GET | (auth only) | No | Canonical OpenAPI contract for v1. |
| `/v1/health` | GET | (auth only) | No | Authenticated health and key sanity check. |
| `/v1/fred/search` | GET | `fred.read` | No | Search FRED series by query. |
| `/v1/fred/series/{series_id}` | GET | `fred.read` | No | Fetch observations for one FRED series. |
| `/v1/mcp/tools` | GET | `mcp.tools.read` | No | Legacy MCP-compatible tool catalog route. |
| `/v1/mcp/invoke` | POST | `mcp.invoke` + tool scope | Yes | Legacy MCP-compatible tool invocation route. |
| `/mcp` | POST | per method | Required for `tools/call` | Hosted MCP protocol endpoint (JSON-RPC over HTTP). |
| `/mcp` | GET | (auth only) | No | Hosted MCP stream transport channel (internal beta; not required by most clients). |
| `/mcp` | DELETE | (auth only) | No | Hosted MCP session close. |
| `/sse` | GET | (auth only) | No | SSE compatibility transport endpoint. |

## `GET /v1/openapi.json`

Fetch the canonical OpenAPI contract for OMNI Client API v1.

Common uses:

- generate clients in Postman / Insomnia / Bruno
- generate typed SDKs in your preferred language
- diff contracts across versions in CI

```bash
curl "https://api.omnibrief.app/v1/openapi.json" \
  -H "Authorization: Bearer omni_live_..."
```

## `GET /v1/health`

Returns `object=health` with `status=ok` when auth succeeds.

```bash
curl "https://api.omnibrief.app/v1/health" \
  -H "Authorization: Bearer omni_live_..." \
  -H "X-Request-Id: req_health_001"
```

Example response:

```json
{
  "object": "health",
  "status": "ok",
  "request_id": "req_health_001",
  "mode": "live"
}
```

## `GET /v1/fred/search`

Query params:

- `q` (required, string)
- `limit` (optional, integer 1-50, default 10)

```bash
curl "https://api.omnibrief.app/v1/fred/search?q=unemployment&limit=5" \
  -H "Authorization: Bearer omni_live_..."
```

Example response (truncated):

```json
{
  "object": "fred.search_result",
  "data": {
    "query": "unemployment",
    "count": 2,
    "results": [
      {
        "series_id": "UNRATE",
        "title": "Unemployment Rate",
        "frequency": "Monthly",
        "units": "Percent"
      }
    ]
  }
}
```


## `POST /v1/mcp/invoke` (legacy compatibility)

```bash
curl -X POST "https://api.omnibrief.app/v1/mcp/invoke" \
  -H "Authorization: Bearer omni_live_..." \
  -H "Idempotency-Key: idem_mcp_legacy_001" \
  -H "Content-Type: application/json" \
  -d '{
    "tool": "fred.search",
    "arguments": {"q": "cpi", "limit": 3}
  }'
```

Example response (shape only):

```json
{
  "object": "mcp.tool_result",
  "tool": "fred.search",
  "data": {}
}
```

## Hosted MCP protocol (`POST /mcp`)

Hosted MCP is the canonical transport for MCP clients. It is a JSON-RPC endpoint with a small number of methods.

Required scopes by method:

| JSON-RPC method | Required scopes |
| --- | --- |
| `initialize` | (auth only) |
| `notifications/initialized` | (auth only) |
| `tools/list` | `mcp.tools.read` |
| `tools/call` | `mcp.invoke` + tool scope (example: `fred.read`) |
| `ping` | (auth only) |

### `initialize`

```bash
curl -X POST "https://api.omnibrief.app/mcp" \
  -H "Authorization: Bearer omni_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {"protocolVersion": "2025-11-05"}
  }'
```

After `initialize`, send `notifications/initialized` (no `id`) before calling tools:

```bash
curl -X POST "https://api.omnibrief.app/mcp" \
  -H "Authorization: Bearer omni_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "notifications/initialized",
    "params": {}
  }'
```

### `tools/list`

```bash
curl -X POST "https://api.omnibrief.app/mcp" \
  -H "Authorization: Bearer omni_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/list",
    "params": {}
  }'
```

### `tools/call`

```bash
curl -X POST "https://api.omnibrief.app/mcp" \
  -H "Authorization: Bearer omni_live_..." \
  -H "Idempotency-Key: idem_mcp_call_001" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "fred.search",
      "arguments": {"q": "inflation", "limit": 5}
    }
  }'
```

## `GET /sse` (compatibility transport)

`/sse` exists for MCP clients that expect an SSE-style bootstrap. New integrations should prefer streamable HTTP via `/mcp`.

## SDK-style examples (raw HTTP)

### TypeScript

```ts
const res = await fetch("https://api.omnibrief.app/v1/fred/search?q=cpi&limit=5", {
  headers: {
    Authorization: `Bearer ${process.env.OMNI_CLIENT_API_KEY}`,
    "X-Request-Id": "req_ts_001",
  },
});
const body = await res.json();
```

### Python

```python
import requests

res = requests.get(
    "https://api.omnibrief.app/v1/fred/search",
    params={"q": "cpi", "limit": 5},
    headers={"Authorization": f"Bearer {OMNI_CLIENT_API_KEY}"},
    timeout=15,
)
body = res.json()
```

### Go

```go
req, _ := http.NewRequest("GET", "https://api.omnibrief.app/v1/fred/search?q=cpi&limit=5", nil)
req.Header.Set("Authorization", "Bearer "+os.Getenv("OMNI_CLIENT_API_KEY"))
resp, err := http.DefaultClient.Do(req)
```
