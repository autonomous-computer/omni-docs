Start with service status, then narrow to the specific request. A reachable service doesn't establish that a particular issuer, filing, or route can satisfy your request - the route's response and its source fields remain the evidence for a data result.

## Check service status

| Surface | Address |
| --- | --- |
| Status page | [status.secapi.ai](https://status.secapi.ai) |
| API | `https://api.secapi.ai` |
| Health | `https://api.secapi.ai/healthz` |
| Readiness | `https://api.secapi.ai/readyz` |

`/healthz` reports service health; `/readyz` reports readiness. If health is successful but your request still fails, work from that request's error and request ID rather than assuming a general outage.

## Diagnose one failed request

1. Review [status.secapi.ai](https://status.secapi.ai), then check `/healthz`.
2. Reproduce the request once with the same endpoint and redacted inputs.
3. Record the UTC timestamp, HTTP status, error `code`, `Request-Id`, and `traceparent` when supplied.
4. Honor `Retry-After` for rate limits. Don't loop on a quota, billing, authorization, or validation response - each states a condition that must change before a retry can succeed.

Common statuses and the first action for each:

| Status | First action |
| --- | --- |
| `400` | Correct the request using the API reference. |
| `401` | Confirm a valid `x-api-key` reached the API. |
| `402` | Resolve the billing or budget condition named in the response. |
| `403` | Check that the key and plan are authorized for the resource. |
| `429` | Honor `Retry-After`; retry with bounded backoff. |
| `5xx` | Retry with bounded backoff, then keep the request ID for support. |

## Contact us

When you contact support, include the UTC timestamp, endpoint, HTTP status, error `code`, and `Request-Id` from the failed request. Never include an API key or a private payload in a support report.

If the response succeeded but looks partial, preserve the stated limitation - don't fill the gap from a different issuer, period, or surface. Include the returned source identifiers so we can trace the data question directly.
