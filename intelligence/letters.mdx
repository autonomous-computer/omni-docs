Fund Letters adds manager commentary to [Track Investors](/workflows/track-investors): permitted investor letters, company mentions, theses, changes in stated views, and page-level citations alongside SEC-reported holdings and ownership disclosures.

The endpoints are live on the production API and return data for keys with fund-letter access. See the [Fund Letters API reference](/api-reference/fund-letters) for parameters and response shapes.

## What you can ask

- Which permitted letters exist for a manager, fund, company, or period? — `GET /v1/fund-letters`
- Where did a manager discuss a company or theme? — `GET /v1/fund-letters/search`, `GET /v1/fund-letters/semantic`
- How did a stated thesis change between letters? — `GET /v1/fund-letters/diff`, `GET /v1/fund-letters/{letter_id}/topics`
- Which companies have extracted theses, and what is the latest stance? — `GET /v1/fund-letters/companies`, `GET /v1/fund-letters/theses`
- What is the one-screen view of a manager? — `GET /v1/fund-letters/managers/{manager_id}/overview`

Every result retains the letter identity, publication or as-of date, document location, and page-level citation needed to review the original passage. Quotes verify against the bytes served by `GET /v1/fund-letters/{letter_id}/document?format=markdown`.

## Coverage boundary

Documented coverage begins with letters published in 2025 Q1 and is not a comprehensive historical archive. Coverage depends on permitted documents, manager and fund identity resolution, extraction quality, and distribution rights. **Do not assume that a missing result means a manager did not publish or discuss something.**

Two boundaries are worth knowing before you build:

- `GET /v1/fund-letters/funds` and `GET /v1/fund-letters/funds/{fund_id}` return `200` with an **empty list today**: the fund-vehicle store has no rows and nothing currently populates it (OMNI-6591). Treat these two routes as not yet carrying data rather than as a signal that a manager has no vehicles, and browse `GET /v1/fund-letters/managers` instead. Every other Fund Letters route returns real data.
- `third_party`-distribution letters return `403 document_not_distributable` from `/document` with a `sourceUrl` hint, and their semantic-search chunks are snippet-capped. `public_record` and `fund_published` letters serve the full document.

## Availability

Fund Letters availability can change independently of the API contract. Check `availability` for the route in the [API catalog](https://www.turos.app/docs/.well-known/api-catalog.json) before you treat a `404` as a missing record: `live` means the endpoints are serving, `gated` means the route returns `404 fund_letters_not_available` regardless of your key.

The related **public embed** surface (`/v1/embed/letters`) is a separate, unauthenticated snippet-only surface and is currently `gated`.
