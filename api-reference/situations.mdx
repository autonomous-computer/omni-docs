Situations routes track filing-derived corporate events - M&A, tender offers, going-private transactions, spin-offs, activist campaigns, restructurings, and bankruptcies - with lifecycle status, deal terms, and a per-filing timeline.

There are two route families with different access models. Choose by audience, not convenience:

| Use case | Route family | Access |
| --- | --- | --- |
| Public site or lightweight browser preview | `/v1/embed/situations` | Anonymous. CORS-enabled, cacheable, capped to a recent public projection. Don't send `x-api-key`. |
| Application, agent, or sustained monitoring | `/v1/situations` | Paid, authenticated with a server-held `x-api-key`. |

## Authenticated routes

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/v1/situations` | List current situations with lifecycle status, deal terms, and market snapshot, filtered and paginated. |
| `GET` | `/v1/situations/{situation_id}` | Get situation. |
| `GET` | `/v1/situations/{situation_id}/filings` | Retrieve a situation's filing timeline as a paginated sub-resource. |
| `GET` | `/v1/situations/{situation_id}/summary` | Retrieve a compact summary: rendered markdown, deal terms, and the latest timeline event. |
| `GET` | `/v1/situations/{situation_id}/export` | Render a source-cited Markdown brief for one situation. |
| `GET` | `/v1/situations/{situation_id}/underwriting-pack` | Retrieve a deterministic, source-cited underwriting pack with detail, timeline, and copyable source context. |
| `GET` | `/v1/situations/by-form/{form}` | List situations opened or advanced by a given EDGAR form type, such as `SC 13D`, `SC TO-T`, `425`, or `DEFM14A`. |
| `GET` | `/v1/situations/feed` | Read a reverse-chronological feed of situation events, each enriched with its parent situation summary. |
| `GET` | `/v1/situations/feed.rss` | Consume the paid authenticated RSS feed of situation events. |
| `GET` | `/v1/situations/calendar` | Return upcoming disclosed key dates - record, vote, expiry, expected close - within a horizon of up to 365 days. |
| `GET` | `/v1/situations/stats` | Return situation counts by type, status, sector, market-cap bucket, and country. |
| `GET` | `/v1/situations/performance` | Return closed-situation outcome cohorts: completion rate, median days to close, average premium. |
| `GET` | `/v1/situations/issues` | List immutable, numbered weekly digest issues. |
| `GET` | `/v1/situations/issues/{issue}` | Retrieve one immutable weekly digest issue by number or slug. |
| `GET` | `/v1/situations/watchlists` | List situation watchlists. |
| `POST` | `/v1/situations/watchlists` | Create situation watchlist. |
| `GET` | `/v1/situations/watchlists/{monitor_id}` | Retrieve a situation-scoped watchlist monitor by ID. |
| `DELETE` | `/v1/situations/watchlists/{monitor_id}` | Deactivate situation watchlist. |

An API key can create a filter-only watchlist. Activating email or webhook delivery requires a signed-in organization session - configure it in the [TUROS dashboard](https://turos.app).

## Public embed routes

The embed routes are a free anonymous preview for logged-out and third-party surfaces:

```bash
curl -sS "https://api.turos.app/v1/embed/situations?types=merger&limit=10"
```

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/v1/embed/situations` | Public capped situations list for logged-out experiences. |
| `GET` | `/v1/embed/situations/{id}` | Public situation detail for permalinks and embeddable discovery surfaces. |
| `GET` | `/v1/embed/situations/{situation_id}/export` | Public Markdown brief for one recent situation. |
| `GET` | `/v1/embed/situations/feed` | Public capped event feed with safe filing provenance. |
| `GET` | `/v1/embed/situations/feed.rss` | Public RSS feed of recent situation events. |
| `GET` | `/v1/embed/situations/issues` | Public capped digest issue archive. |
| `GET` | `/v1/embed/situations/issues/{issue}` | Public digest issue detail by number or slug. |
| `GET` | `/v1/embed/situations/stats` | Public recent-window situation counts with coverage scope. |
| `GET` | `/v1/embed/widget.js` | Embeddable feed widget script that renders the situations feed into a host element. |

## Interpretation boundaries

Current situation detail changes as new filings arrive; a digest issue is an immutable publication-time snapshot. A situation record doesn't confirm that a transaction will close or that a disclosed date, term, or status remains current - review the underlying filing before relying on it, and keep filing identities and `requestId` with derived output.
