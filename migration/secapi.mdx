SECAPI.ai is now TUROS API and TUROS MCP. This is a brand and host migration, not permission to break working integrations.

For the broader evaluation and migration path, see [Switch to TUROS](https://www.turos.app/switch). You can compare representative workflows before changing any production integration.

## Hosts

- `https://api.turos.app` is the production API and MCP host. New integrations, examples, and discovery documents use it.
- `https://api.secapi.ai` is a permanently supported compatibility alias. It serves the same methods, request bodies, authentication, errors, streaming, CORS, billing, and discovery as `api.turos.app`, and it has no end date.
- API requests are never redirected between hosts. A client that keeps `api.secapi.ai` configured continues to work unchanged.

## What stays compatible

- Existing API keys, paths, request bodies, headers, and pinned versions continue to work on both hosts.
- Current SDK package names, CLI commands, and environment variables (`@secapi/sdk-js`, `secapi-client`, `secapi`, `SECAPI_API_KEY`, `secapi_live_…` key prefixes) remain valid. They are compatibility contracts, not stale branding.
- Billing, quotas, and idempotency keys are shared across hosts: the same organization, wallet, and rate limits apply whichever host a request reaches.

## What changes

- Documentation and product language use **TUROS API** and **TUROS MCP**.
- Canonical documentation lives at `https://www.turos.app/docs`; the retired SECAPI.ai documentation redirects to the closest TUROS equivalent.
- New examples and the OpenAPI `servers` list put `api.turos.app` first, with `api.secapi.ai` listed as the alias.

## Moving an existing client to `api.turos.app`

Moving is optional. If you choose to, the base URL is the only change:

1. Confirm the current integration works on `api.secapi.ai` and record a representative request, its `requestId`, and the entity and filing identifiers it returns.
2. Change the base URL (or the SDK `base_url` / `baseUrl` option) to `https://api.turos.app`. Keep the same API key, version header, and request shape.
3. Verify with `GET /v1/limits`, then replay the recorded request and compare identifiers, response fields, and billing headers.

Do not rename environment variables or SDK imports merely to make the branding look newer. Compatibility identifiers are part of the integration contract.
