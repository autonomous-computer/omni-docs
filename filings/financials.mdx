---
title: "Financial statements"
description: "Retrieve normalized statements and XBRL facts from SEC filings, and compare values without mixing reporting periods"
---

TUROS normalizes the financial content of filings into two shapes. A statement is a full financials page - balance sheet, income statement, or cash flow statement - with rows, periods, and provenance. A fact is one disclosed number: a single XBRL observation with its concept, unit, and period. Ask for the shape that matches the question.

Both resolve US GAAP 10-K / 10-Q filers and, where applicable, IFRS foreign private issuers through `ifrs-full` 20-F / 6-K coverage.

## Retrieve a statement

Supply one issuer identifier, set `statement`, and anchor the reporting slice with `period` or a fiscal year:

```bash
curl --fail-with-body -sS \
  -H "x-api-key: $SECAPI_API_KEY" \
  -H "secapi-version: 2026-03-19" \
  "https://api.turos.app/v1/statements?ticker=AAPL&statement=income_statement&period=annual"
```

Use `GET /v1/statements/all` when you need the annual or quarterly balance-sheet, income-statement, and cash-flow bundle in one response. Read the returned periods, provenance, completeness, and freshness metadata alongside the rows - a missing normalized line item is not zero, and it's not evidence the issuer made no disclosure.

<Warning>
Check `periodBasis` before comparing values. Balance-sheet values are point-in-time, but quarterly income-statement and cash-flow values can be year-to-date as filed. Comparing a `fiscal_year_to_date` value against a discrete quarter produces a wrong answer that looks right.
</Warning>

Also compare units, reporting periods, and source context before treating values as comparable. Values from different units, periods, or filing scopes shouldn't be combined without normalization.

## Retrieve individual facts

When the question is one number rather than a page, use facts:

```bash
curl --fail-with-body -sS \
  -H "x-api-key: $SECAPI_API_KEY" \
  -H "secapi-version: 2026-03-19" \
  "https://api.turos.app/v1/facts?ticker=AAPL&tag=Revenues&form=10-K&limit=6"
```

Omit `tag` to receive the common financial metrics, or pass an XBRL concept such as `Revenues` or `NetIncomeLoss` for a concept-specific series. Use `taxonomy`, `form`, `unit`, and fiscal-year filters to avoid mixing concepts, periods, or units. Read `requestedTag`, `resolvedTag`, `aliasStrategy`, and `completeness` before treating a series as a like-for-like historical comparison - the route can resolve an alias, and you should know when it did.

## Segments (beta)

`GET /v1/companies/segments` returns a multi-axis, revenue-anchored breakdown of a company's business: product, geographic, and operating axes with segment revenue, profit, margin, and year-over-year growth. Responses carry `SECAPI-Maturity: beta`.

```bash
curl --fail-with-body -sS \
  -H "x-api-key: $SECAPI_API_KEY" \
  "https://api.turos.app/v1/companies/segments?ticker=AAPL&period=annual"
```

Each axis reports whether it `tiesToRevenue`. Axes flagged `low_confidence` - common for banks, REITs, and insurers, whose segment basis is net revenue, premiums, or rental income rather than GAAP total revenue - are surfaced, not hidden. Treat them as directional. An empty `segments` array with a `note` is a successful response for single-activity issuers, not an error. Under load the endpoint can return `429` with `Retry-After`; retry shortly.

## Keep the source attached

Statements and facts are normalized views over filings, not a substitute for the cited filing. Preserve `provenance`, the accession number, filing URL, units, and periods with every value you store, so a later comparison doesn't collapse reporting periods into a current-state claim.
